## 블록 0. 오리엔테이션 (20분) — 교재 시작하기

### 목표
오늘의 환자(연습용 앱)를 받아서 실행해보기

### 0-1. 앱 받기 (8분)
```bash
mkdir -p ~/projects && cd ~/projects    # 홈(~) 아래 projects 폴더를 만들고(-p = 이미 있으면 그냥 넘어감) 그 폴더로 이동. && = 앞 명령이 성공하면 뒤 명령 실행
git clone https://github.com/NujabesCode/Harness.git harness-material  # GitHub 의 강의 자료 저장소 전체를 내 컴퓨터에 복사. 끝의 harness-material = 내 컴퓨터에 새로 만들 폴더 이름
cp -r harness-material/claude-team/library-app ./library-app  # 받은 자료 중 연습용 앱 폴더만 지금 위치(./)로 복사. -r = 폴더 안의 파일까지 통째로
cd library-app                          # 복사한 앱 폴더로 들어가기
git init                                # 이 폴더를 새 git 저장소로 시작 (.git 숨김 폴더 생성) → 강의 자료와 상관없는 나만의 기록
git add . && git commit -m "init: 연습용 도서 대출 앱"  # 모든 파일을 담고(add .) 첫 세이브(commit). -m = 커밋 메시지
```

### 0-2. 실행해보기 (7분)
```bash
npm test   # package.json 의 test 스크립트(node --test) 실행 → test/ 폴더의 테스트를 돌림 (테스트 2개 통과 확인)
npm start  # package.json 의 start 스크립트(node server.js) 실행 → 서버 시작, 끌 때는 Ctrl + C (http://localhost:3000)
```
브라우저에서: 가입 → 로그인 → 검색 → **대출** → **반납** 눌러보기 → 터미널에서 **Ctrl + C** 로 서버 끄기

> ⚠️ 이 앱에는 **일부러 심어둔 문제가 10개 이상** 있습니다. 오늘 클로드 팀이 찾고 고칩니다.

### 0-3. 오늘의 목표 선언 (5분)

교재 9쪽의 **혼자 · 심부름꾼 · 팀** 표를 같이 읽기

## 블록 2. 팀 켜기 + 첫 팀 (30분) — 교재 3~6단계

### 목표
팀 기능을 켜고, **팀원 현황판** 조작에 익숙해지기

### 2-1. 팀 기능 켜기 (7분)
```
이 프로젝트의 .claude/settings.json 에 env 로 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 을 추가해줘.
기존 설정이 있으면 합쳐줘. 저장 후 파일 전체를 보여줘.
```
결과가 이렇게 생겼는지 확인:
```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```
→ `/exit` 후 `claude` 로 다시 시작 (깨끗한 상태에서 시작)

### 2-2. 첫 팀: 예약 기능 기획 회의 (15분)
오늘 오후에 만들 **"예약 기능"** 을 팀으로 먼저 생각해봅니다. 세 역할은 **서로 기다릴 필요가 없어서** 첫 팀으로 좋습니다.
```
이 도서 대출 앱에 "예약 기능"(재고가 0인 책을 예약해두면 반납될 때 순서대로 받을 수 있는 기능)을 추가하려고 해.
agent team 으로 팀원 3명을 뽑아줘. 이름은 ux, arch, critic, 모델은 모두 Sonnet.
- ux: 사용자 입장에서 화면 흐름과 안내 문구
- arch: 데이터 구조와 API 설계 (src/books.js, server.js 기준)
- critic: 악마의 변호인. 이 기능의 문제점과 빠뜨린 경우를 찾기
코드는 고치지 말고, 결과를 합쳐서 docs/reservation-plan.md 에 써줘.
```

### 2-3. 현황판 조작 연습 (8분) — 팀이 일하는 동안
| 해보기 | 키 |
|---|---|
| 팀원 고르기 | **↑ / ↓** (입력창 아래 현황판) |
| 그 팀원 화면 보기 | **Enter** |
| 팀장 화면으로 돌아오기 | **Esc** (⚠️ 팀원 화면에서 Esc 는 그 팀원 작업을 멈춤 → 한 번 실험해보고 "계속해" 라고 말해주기) |
| 할 일 보드 | **Ctrl + T** |

→ critic 화면에 들어가서 **직접 말 걸기**:
```
초등학생이 쓴다고 생각하고 문제점을 하나 더 찾아봐.
```

끝나면:
```
팀원 모두 퇴근시켜줘.
```

## 블록 3. 🔍 리뷰 팀 — 혼자 vs 팀 대결 (50분) — 교재 7, 11단계

### 목표
같은 코드를 **혼자 리뷰** 한 것과 **팀으로 리뷰** 한 것을 비교해서, 팀이 언제 이득인지 직접 확인

### 3-1. 🧑 혼자 리뷰 (10분) — 기준점
**새 터미널**을 하나 더 열고 (팀 설정과 상관없는 깨끗한 대화):
```bash
cd ~/projects/library-app && claude  # 앱 폴더로 이동한 뒤 새 클로드 대화 시작
```
```
이 앱의 문제점을 리뷰해줘. 보안, 성능, 버그, 테스트 부족 무엇이든.
코드는 고치지 말고, 문제마다 한 줄씩 번호를 매겨서 docs/review-solo.md 에 써줘.
```
→ 몇 개 찾았는지 **숫자를 칠판에** 적기 → 이 터미널은 `/exit`

### 3-2. 역할 카드 3장 (10분)
원래 터미널(팀 켜진 세션)에서:
```
.claude/agents/ 에 팀원용 역할 카드 3개를 만들어줘: security-reviewer, perf-reviewer, test-reviewer.
- 모두 tools 는 Read, Glob, Grep, Bash (Bash 는 재현용으로만, 파일 수정 금지)
- model: sonnet
- 결과는 표로: 번호 | 심각도(높음/중간/낮음) | 파일:줄 | 문제 | 재현 방법 | 고치는 방법
- 추측이면 "추측" 이라고 표시
각 카드의 description 은 그 역할이 언제 쓰이는지 분명하게.
```

### 3-3. 🏢 팀 리뷰 (20분)
```
agent team 으로 리뷰 팀을 꾸려줘. 팀원 3명:
- sec: security-reviewer 에이전트 타입. src/auth.js, server.js, public/index.html 의 보안
- perf: perf-reviewer 에이전트 타입. src/books.js, server.js 의 성능·안정성(서버가 죽을 수 있는 경우 포함)
- test: test-reviewer 에이전트 타입. src/books.js 의 로직 버그와 test/ 의 빠진 테스트

③ 할 일 보드 초안: 팀원당 4~6개, 선행 작업
④ 결과물: 어떤 파일에 무엇이 남는가
⑤ 안전장치: 시작 전 커밋, 검문소(hook) 필요 여부
```

### 8-2. 가동 (55분)
- 업무 지시서 → **내가 먼저 확인** → 팀원 뽑기
- 10분마다 **현황판·할 일 보드** 들여다보기
- 끝난 팀원은 **바로 퇴근**
- `/usage` 로 시작 전·후 사용량 메모

### 8-3. 회고 메모 (15분)
1. 팀이 정말 필요했나? (다시 한다면 혼자 / 심부름꾼 / 팀?)
2. 팀원이 엇나간 순간과 어떻게 바로잡았나
3. 사용량은 얼마나 썼고, 그만한 가치가 있었나

### 🧑‍🏫 강사 운영 팁
- 자리를 돌며 **"① 왜 팀이어야 해요?"** 부터 묻기. 답이 약하면 ⭐ 로 유도
- 마우스·키보드 잡지 않기. **"지금 팀장이 뭘 기다리고 있어요?"** 만 묻기
- 사용량 한도에 걸린 학생 → 짝꿍 화면에서 같이 (설계서는 각자 발표)

### ✅ 체크포인트
- [ ] 팀 설계서 ① 에 답했다
- [ ] 팀원 업무 지시서를 먼저 확인했다
- [ ] 결과물 파일이 있고, 팀원을 모두 퇴근시켰다

## 부록 C. 🔒 강사용 정답지 — 연습용 앱에 심어둔 문제

> 블록 3-4 에서 공개. 학생 리뷰가 아래와 다른 **진짜 문제**를 찾으면 가산점.

### 보안 (S)
| # | 파일 | 문제 | 재현 |
|---|---|---|---|
| S1 | `src/auth.js` | 비밀번호를 **평문**으로 저장 | 코드 확인 |
| S2 | `src/auth.js` `signup` | 같은 아이디로 가입하면 **기존 계정 비밀번호를 덮어씀** (계정 탈취) | `hong` 으로 두 번 가입 → 두 번째 비밀번호로 로그인됨 |
| S3 | `src/auth.js` `login` | `users[username] == password` → **없는 아이디 + 비밀번호 생략** 시 `undefined == undefined` 로 로그인 성공 | `curl -XPOST localhost:3000/api/login -d '{"username":"nobody"}'` → 토큰 발급 |
| S4 | `src/auth.js` `verify` | 토큰 = 아이디의 base64. 서명이 없어 **누구나 위조** | `Authorization: $(echo -n hacker \| base64)` 로 대출 성공 |
| S5 | `server.js` 정적 파일 | `path.join('public', req.url)` → **경로 탈출**로 서버 소스 노출 | `curl --path-as-is http://localhost:3000/../server.js` |
| S6 | `public/index.html` | 책 제목·저자를 `innerHTML` 로 출력 → **XSS** 위험 (데이터에 HTML 이 들어오면 실행) | 코드 확인 |

### 성능·안정성 (P)
| # | 파일 | 문제 | 재현 |
|---|---|---|---|
| P1 | `server.js` `readBody` | `JSON.parse` 에 try/catch 없음 → **잘못된 JSON 한 번에 서버 전체 다운** | `curl -XPOST localhost:3000/api/login -d '{bad'` → 서버 종료 |
| P2 | `src/books.js` | 요청마다 `readFileSync`/`writeFileSync` 로 파일 전체를 **동기** 읽기·쓰기 | 코드 확인 |
