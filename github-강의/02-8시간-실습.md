- 학원 네트워크에서 `github.com`, `*.github.io` 접속 확인

### 🎯 지루함 방지 규칙 (강사용)

## 블록 1. 터미널 생존 훈련 (40분) — 교재 1단계

### 목표
마우스 없이 폴더를 만들고, 이동하고, 내용을 볼 수 있다

### 1-1. 프롬프트 읽기 (5분)
```
nujabes@MY-PC MINGW64 ~
$
```
→ "`~` 가 뭐지?" "지금 어디야?" 를 같이 확인
```bash
pwd
ls
```

### 1-2. 따라 치기 (15분)
한 줄씩 치고, 매번 **`pwd` 나 `ls` 로 결과 확인**
```bash
cd ~
mkdir projects
cd projects
mkdir my-site
cd my-site
pwd                 # .../projects/my-site 인지 확인
touch index.html
ls
cd ..
pwd                 # 한 칸 위로 왔는지
ls                  # my-site 폴더가 보이는지
cd my-site
code .              # VS Code 로 이 폴더 열기
```
💬 **질문 던지기**: "`cd ..` 를 두 번 치면 어디로 갈까요?" → 직접 쳐보고 `pwd`

### 1-3. 🎮 폴더 미로 보물찾기 (15분, 짝꿍)
**A 가 미로를 만들고 → B 가 `cd`, `ls`, `cat` 만으로 보물을 찾습니다.** (마우스·탐색기 금지)

A 가 만들기 (`~/projects` 에서):
```bash
mkdir -p maze/left/dark maze/left/cave maze/right/light/deep maze/right/forest
echo "꽝! 다른 길로" > maze/left/dark/note.txt
echo "보물: 🍩 도넛 쿠폰" > maze/right/light/deep/treasure.txt
echo "숨겨진 힌트: right 로 가" > maze/.hint
```
- `mkdir -p` = 중간 폴더까지 한 번에 만들기
- `echo "글자" > 파일` = 파일에 글자 쓰기

B 가 찾기 — 힌트: **`ls -a`** 를 쓰면 숨겨진 파일이 보입니다
```bash
cd ~/projects/maze
ls -a
cat .hint
cd right
...
```
→ 찾으면 `cat treasure.txt` 화면을 들어 올리기 🍩 → 역할 바꿔서 한 번 더
💡 **Tab 자동완성**을 쓰면 2배 빠릅니다. 강사가 Tab 쓰는 사람에게 보너스 점수

다 끝나면 정리:
```bash
cd ~/projects
rm -rf maze
```

### 1-4. 손가락 단축키 (5분)
```bash
sleep 100           # 100초 동안 멈춤 → Ctrl + C 로 강제 종료해보기
```
- **↑** 키로 방금 친 명령 다시 불러오기
- **Tab** 두 번 = 후보 목록 보기 (`cd ` 치고 Tab Tab)
- **`clear`** 또는 **Ctrl + L** 로 화면 정리

### ✅ 체크포인트
- [ ] `~/projects/my-site` 폴더가 있고 VS Code 로 열려 있다
- [ ] `ls -a` 로 숨긴 파일을 찾았다
- [ ] Ctrl + C 로 멈추는 법을 안다

⭐ 보너스: `ls -la` 의 결과에서 날짜와 파일 크기가 어디 있는지 찾기
🆘 따라잡기: `mkdir -p ~/projects/my-site && cd ~/projects/my-site && code .`

## 블록 2. Git 설정 + 첫 세이브 (30분) — 교재 2~4단계

### 목표
내 이름이 찍힌 **첫 세이브 포인트** 만들기

### 2-1. Git 첫 설정 (10분, 컴퓨터마다 한 번)
```bash
git config --global user.name "내 이름"
git config --global user.email "GitHub-가입-이메일"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"
git config --global pull.rebase false
git config --global core.autocrlf true          # Windows 만
git config --global --list                       # 확인
```
💬 **질문 던지기**: "`--global` 을 빼면 어떻게 될까요?" (→ 지금 폴더 저장소에만 적용)

### 2-2. 저장소 만들기 (5분)
```bash
cd ~/projects/my-site
pwd
git init
ls -a               # .git 이 생겼다!
git status
```
→ `No commits yet` 를 같이 소리 내어 읽기

### 2-3. 클로드로 사이트 뼈대 만들기 (10분)
```bash
claude
```
```
이 폴더에 순수 HTML/CSS/JS 로 된 내 자기소개 웹사이트를 만들어줘.
- index.html, style.css, script.js 세 파일만 (npm, 빌드 도구 쓰지 마)
- 섹션: 헤더(이름 + 한 줄 소개) / 소개 / 좋아하는 것 3가지 / 푸터
- 이름은 "홍길동" 으로 임시로 넣어줘
- git 명령은 실행하지 마. 커밋은 내가 직접 할 거야.
```
브라우저로 확인 (**터미널을 하나 더 열어서**, VS Code 터미널 `+` 버튼):
```bash
cd ~/projects/my-site
start index.html     # mac: open index.html
```

### 2-4. 첫 커밋 — 내 손으로 (5분)
```bash
git status                                  # 🔴 빨간 파일 3개
git add .
git status                                  # 🟢 초록으로 바뀜
git commit -m "feat: 자기소개 사이트 뼈대"
git log --oneline                           # 첫 세이브 번호 확인!
```

### ✅ 체크포인트
- [ ] `git log --oneline` 에 커밋 1개가 보인다
- [ ] `git status` 가 `nothing to commit, working tree clean`
- [ ] 브라우저에 사이트가 뜬다

🆘 따라잡기: `Author identity unknown` 이 나오면 2-1 의 `user.name`, `user.email` 두 줄만 다시

## 블록 3. 세이브 쌓기 + AI 검수 (50분) — 교재 4~5단계

### 목표
**"시킨다 → diff 로 검수 → add → commit"** 루틴을 손에 익히기 (6번 반복)

> 📌 매 미션마다 똑같이:
> ```bash
> git status
> git diff            # 클로드가 뭘 바꿨는지 직접 읽기
> git add .
> git commit -m "타입: 설명"
> ```

### 미션 1. 내 정보 채우기 — 직접 편집 (7분)
**클로드 없이** VS Code 에서 `index.html` 의 이름과 소개를 **진짜 내 것으로** 고치기. (전화번호·주소 같은 개인정보는 쓰지 않기 — 오후에 인터넷에 공개됩니다)
```bash
git diff
```
→ 내가 고친 줄이 `-` 빨강 / `+` 초록으로 보이는지 확인
```bash
git add index.html
git commit -m "feat: 내 소개 내용 채우기"
```

### 미션 2. 카드 디자인 (7분)
```
좋아하는 것 3가지 섹션을 카드 3개가 가로로 놓이는 디자인으로 바꿔줘. git 명령은 실행하지 마.
```
→ `git diff --stat` 먼저 (**어떤 파일이 몇 줄** 바뀌었나) → `git diff` → 커밋 `feat: 좋아하는 것 카드 디자인`

### 미션 3. 색상 바꾸기 (6분)
```
사이트 전체 색상을 파스텔톤으로 바꿔줘. git 명령은 실행하지 마.
```
→ diff 확인 → 커밋 `style: 파스텔톤 색상 적용`
💬 **질문 던지기**: "이번 diff 에 `index.html` 이 들어 있나요? 색만 바꾸랬는데 HTML 은 왜 바뀌었을까?"

### 미션 4. 두 가지 일 → 두 커밋으로 나누기 (10분)
```
두 가지를 해줘. git 명령은 실행하지 마.
1. script.js 에 푸터의 연도를 올해로 자동 표시하는 코드 추가 (index.html 에 필요한 태그도)
2. style.css 에서 본문 글자 크기를 조금 키워줘
```
→ **파일별로 골라 담기** (교재 4단계 "택배 상자")
```bash
git status
git add script.js index.html
git commit -m "feat: 푸터 연도 자동 표시"
git add style.css
git commit -m "style: 본문 글자 크기 키우기"
git log --oneline
```

### 미션 5. 🎮 diff 스파이 게임 (12분, 짝꿍)
1. A 가 B 의 자리에서, B 가 안 보는 동안 클로드에게 **아주 작은 변경**을 몰래 시킴
   (예: "소개 문단의 단어 하나를 바꿔줘", "카드 하나의 배경색만 살짝 바꿔줘")
2. B 는 **`git diff` 만으로** 무엇이 바뀌었는지 1분 안에 맞히기
3. 맞혔으면 되돌리기 (다음 블록 예고!)
```bash
git restore .
git status          # clean 이면 원상복구 완료
```
4. 역할 바꾸기

### 미션 6. 기록 구경 (8분)
```bash
git log --oneline
git show <두번째-커밋-번호>          # 그 세이브에서 뭘 바꿨나
git log --oneline --stat -3         # 최근 3개 커밋이 건드린 파일
```
클로드에게 읽혀보기:
```
git log --oneline 을 보고 지금까지 내가 한 작업을 한 문장씩 요약해줘. git 명령은 읽기 전용만 써.
```

### ✅ 체크포인트

- [ ] 모든 메시지가 `타입: 설명` 형식
- [ ] diff 스파이 게임에서 1번 이상 맞혔다

⭐ 보너스: `git log --oneline --graph --all` 과 `git log -p -1` 이 각각 뭘 보여주는지 짝꿍에게 설명하기

## 블록 4. 타임머신 + .gitignore (40분) — 교재 6~7단계

### 목표
**AI 가 망쳐도 1분 안에 원상복구** + 비밀 파일 안 올리기

### 4-1. 🔥 AI 사고 복구 훈련 — 커밋 전 (12분)
먼저 지금이 깨끗한 세이브 상태인지 확인 (`git status` → clean). 그다음 **일부러 망치는 프롬프트**:
```
style.css 내용을 전부 지우고 아주 이상한 디자인으로 새로 써줘.
index.html 의 소개 문단도 전부 지워줘. 그리고 junk1.txt, junk2.txt 파일도 아무 내용으로 만들어줘.
git 명령은 실행하지 마.
```
→ 브라우저 새로고침: 망가졌다 😱 → **타이머 시작!**
```bash
git status                 # 수정된 파일 + 새 파일(junk) 확인
git diff --stat
git restore .              # 수정된 파일 원래대로
git status                 # junk 파일은 아직 남아 있음 (Untracked)
git clean -n               # 지워질 파일 미리보기
git clean -fd              # 진짜 삭제
git status                 # clean!
```
→ 브라우저 새로고침: 원상복구 🎉 **목표 1분 이내.** 한 번 더 반복해서 시간 줄이기

### 4-2. 🔥 커밋까지 해버린 사고 (10분)
```
script.js 를 전부 지우고 "console.log('망함')" 한 줄만 남겨줘. git 명령은 실행하지 마.
```
```bash
git add . && git commit -m "fix: 대충 고침"     # 실수로 세이브까지 함
git log --oneline
```
**방법 1 — reset (push 전에만!)**
```bash
git reset --soft HEAD~1    # 커밋만 취소. 변경은 상자에 남아 있음
git status                 # 🟢 초록
git restore --staged .     # 상자에서 빼기
git restore .              # 변경 버리기
git log --oneline          # "fix: 대충 고침" 이 사라짐
```
같은 사고를 한 번 더 내고, **방법 2 — revert**
```bash
git add . && git commit -m "fix: 대충 고침"
git revert --no-edit HEAD  # "취소 커밋"을 새로 만듦
git log --oneline          # 사고 커밋 + Revert 커밋 둘 다 남아 있음
```
💬 **질문 던지기**: "reset 은 기록이 사라졌고 revert 는 남았어요. 친구와 같이 쓰는 저장소라면 어느 쪽이 안전할까요?"

### 4-3. 서랍: stash (5분)
```
헤더에 메뉴 링크 3개(소개, 좋아하는 것, 연락처)를 추가해줘. git 명령은 실행하지 마.
```
→ 작업 중에 "급한 일" 발생 상황
```bash
git stash                  # 서랍에 넣기
git status                 # clean — 브라우저에서도 메뉴 사라짐
git stash list
git stash pop              # 다시 꺼내기 — 메뉴 돌아옴
git add . && git commit -m "feat: 헤더 메뉴 추가"
```

### 4-4. 🔥 .env 함정 (13분)
가짜 API 키 파일을 만들어봅니다. (**진짜 키는 절대 쓰지 않기**)
```bash
echo "API_KEY=sk-test-1234-가짜키" > .env
echo "debug log" > debug.log
git status                 # .env 가 빨간색으로 보인다 → 이대로 git add . 하면 올라감!
```
클로드에게:
```
이 프로젝트용 .gitignore 를 만들어줘. .env, .env.* 는 무시하되 .env.example 은 올라가게,
*.log, .DS_Store, Thumbs.db, node_modules/ 도 넣어줘. git 명령은 실행하지 마.
```
```bash
git status                 # .env 와 debug.log 가 사라지고 .gitignore 만 보임
git add .gitignore
git commit -m "chore: .gitignore 추가"
```
**이미 올라간 파일은?** — 일부러 재현
```bash
git add -f debug.log       # -f = ignore 무시하고 강제로 담기 (실습용)
git commit -m "chore: 로그 파일 실수로 추가"
git rm --cached debug.log  # 추적만 끊기 (파일은 내 컴퓨터에 남음)
git commit -m "chore: 로그 파일 추적 중단"
ls                         # debug.log 는 여전히 있음
git status                 # 하지만 Git 은 신경 안 씀
```

### ✅ 체크포인트
- [ ] 4-1 사고를 **1분 안에** 복구했다
- [ ] reset 과 revert 의 차이를 한 문장으로 말할 수 있다
- [ ] `.env` 가 `git status` 에 안 보인다

### 퀴즈 1. 상황 → 명령어 스피드 게임 (10분, 팀 대항)
강사가 상황을 말하면 → 먼저 **명령어**를 외치는 팀이 점수
| 상황 | 정답 |
|---|---|
| 지금 무슨 폴더야? | `pwd` |
| 클로드가 뭘 바꿨는지 보고 싶어 | `git diff` |
| 상자에 담긴 걸 보고 싶어 | `git diff --staged` |
| index.html 만 세이브에 넣고 싶어 | `git add index.html` |
| 세이브 목록 한 줄씩 | `git log --oneline` |
| 커밋 안 한 수정 전부 되돌리기 | `git restore .` |
| 클로드가 만든 새 파일 지우기 (미리보기) | `git clean -n` |
| 방금 커밋 취소, 변경은 살리기 (push 전) | `git reset --soft HEAD~1` |
| 이미 공유한 커밋 취소 | `git revert 커밋번호` |
| 하던 거 잠깐 치워두기 | `git stash` |

### 퀴즈 2. "Yes 눌러도 돼?" O/X 게임 (10분)
화면에 클로드의 실행 확인창을 띄우고 → 학생들이 **Yes / No / 물어본다** 중 손으로 표시
| 클로드가 실행하려는 명령 | 정답 |
|---|---|
| `git status` | ✅ Yes (아무것도 안 바꿈) |
| `git log --oneline -10` | ✅ Yes |
| `git add .` | 🤔 `git status` 로 뭐가 담기는지 먼저 |
| `git commit -m "feat: 카드 추가"` | ✅ diff 를 봤다면 Yes |
| `git restore --staged style.css` | ✅ Yes (상자에서 빼기만) |
| `git clean -fd` | 🤔 `-n` 미리보기 먼저 |
| `git reset --hard HEAD~3` | ❌ No — 커밋 3개 + 작업 영구 삭제 |
| `git push --force` | ❌ No — 남의 기록 삭제 |
| `rm -rf .git` | ❌❌ 절대 No — 모든 기록 증발 |
| `git revert --no-edit HEAD` | ✅ Yes (취소 커밋 추가, 안전) |

- A: `<h1>` 를 **"A가 정한 제목"** 으로 (예: `<h1>🌸 봄반 방명록</h1>`)
- B: `<h1>` 를 **"B가 정한 제목"** 으로 (예: `<h1>🔥 열정반 방명록</h1>`)
```bash
git add . && git commit -m "style: 제목 변경"
git push -u origin feat/title-내이름
gh pr create --fill
```
**A 의 PR 을 먼저 합칩니다** → B 의 PR 화면을 새로고침하면: **"This branch has conflicts that must be resolved"** 😱

**B 가 터미널에서 해결**
```bash
git switch main && git pull                 # A 의 제목이 들어간 main
git switch feat/title-B이름
git merge main
```
```
CONFLICT (content): Merge conflict in index.html
Automatic merge failed; fix conflicts and then commit the result.
```
```bash
git status                                  # both modified: index.html
code index.html
```
→ `<<<<<<<` `=======` `>>>>>>>` 찾기 → **둘이 상의해서** 최종 제목 결정 (예: `<h1>🌸🔥 봄열정반 방명록</h1>`) → 표시 3줄 지우기
```bash
git diff                                    # 표시가 남았는지 확인
git add index.html
git commit -m "merge: 제목 충돌 해결"
git push
```
→ PR 새로고침: 충돌 해결됨 ✅ → A 가 merge → 둘 다 `git switch main && git pull`

⭐ 시간 남으면 **역할 바꿔서** 한 번 더 (이번엔 B 의 PR 을 먼저 합치기)

### 7-5. 🔥 push 거절 체험 (10분)
**일부러 규칙을 어기고** 둘 다 main 에서 직접 작업해봅니다.
```bash
git switch main && git pull
#   둘 다: index.html 맨 아래에 <footer> 를 각자 다른 문구로 추가
git add . && git commit -m "feat: 푸터 추가"

```
→ 먼저 push 한 사람은 성공, 늦은 사람은:
```
 ! [rejected]        main -> main (fetch first)
hint: Updates were rejected because the remote contains work that you do not have locally.
```
```bash
git pull               # 편집기가 열리면 merge 메시지 확인 후 저장·닫기 / 충돌 나면 7-4 처럼 해결
git push
```
💬 **질문 던지기**: "여기서 `git push --force` 를 쳤다면 무슨 일이?" → 짝꿍의 푸터가 **사라짐**
→ 그래서 **main 에서 직접 작업하지 않는다** (블록 9 에서 아예 잠급니다)
